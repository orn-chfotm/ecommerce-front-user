# 협업

## 언어

- 설명은 한국어로 한다.
- 기존 파일이 명확히 한국어를 사용하지 않는 한 코드, 식별자, 주석, 커밋 메시지, 명령어 이름은 영어로 작성한다.

## 수정 전

- 가정을 명시한다.
- 여러 해석이 가능하면 조용히 하나를 고르지 말고 선택지를 제시한다.
- 요청이 불명확해서 구현 방향이 틀어질 수 있으면 멈추고 질문한다.
- 요청을 만족하는 가장 단순한 구현을 우선한다.

## 구현

- 추측성 기능을 추가하지 않는다.
- 작업에 필요하지 않으면 인접 코드를 리팩터링하지 않는다.
- 다른 스타일이 더 깔끔해 보여도 기존 스타일을 따른다.
- 모든 변경 라인은 사용자 요청과 연결되어야 한다.

## 리뷰 및 보고

- 트레이드오프와 불확실성을 드러낸다.
- 실패한 명령이나 부분 검증 상태를 숨기지 않는다.
- 최종 보고에는 변경 파일과 검증 결과를 포함한다.
